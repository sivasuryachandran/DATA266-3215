Notes / warnings seen during this run:
  - The `wikipedia` package defaults its API_URL to http://, which Wikipedia now rejects with
    403. Patched to https:// before importing WikipediaLoader.
  - DeprecationWarning: `langchain-community` is being sunset. Non-fatal; WikipediaLoader
    still works.
  - "Token indices sequence length is longer than the specified maximum sequence length for
    this model (604 > 512)" during the 1000/100 rerun. flan-t5-base has a 512-token limit and
    three 1000-char chunks exceed it, so the tail of the context is truncated. This is part of
    why the larger chunk size performed worse on the Inception question, not just a cosmetic
    warning.
  - The Yes/No retrieval column is generated by a keyword-hint match as a first pass; every
    retrieved chunk was then read by hand against the ground-truth passage before the column
    was accepted.

Notes on this run:
  - Activation checkpointing was originally measured at the shared batch size of 256 and
    showed a 0.2% memory saving for 42.7% more time, i.e. no benefit. That result was an
    artifact of the configuration, not the technique: at batch 256 the 360.4 MB fixed floor is
    nearly the whole 380.7 MB peak, leaving almost no activation memory to reclaim. The
    section was rewritten to sweep batch size and segment count, re-measuring the baseline at
    each batch size. See AI_USE.md for the full write-up.
  - Loss is unchanged to four decimals with checkpointing on vs off (2.3026), which is the
    correctness check: recomputation is mathematically a no-op, so a loss change would mean
    broken gradients.
  - Gradient accumulation's peak memory came out HIGHER than the baseline (880.0 vs 622.0 MB),
    the opposite of the expected direction. Logged as measured. At this model size the
    activation saving from a 64- vs 256-example batch is only a few MB, so the number is
    dominated by PyTorch caching-allocator fragmentation across the extra forward/backward
    cycles rather than by the technique itself.
  - Mixed precision also increased peak memory (+11.1%) while cutting time 1.83x -- the fp32
    master weights and GradScaler state outweigh the fp16 activation saving at this size.
  - The GradScaler FutureWarning is cosmetic; `torch.cuda.amp.GradScaler` still functions in
    the installed torch version.
  - The prose commentary cells in the notebook were drafted against an earlier execution of
    the same experiments and cite slightly different wall-clock numbers (e.g. 98s/3.3s for the
    CPU-vs-GPU comparison). The authoritative numbers are the executed cell outputs
    reproduced above and carried into METRICS.md.
